Video Comment Overlay / policy board

動画を抜くツールではなく、素材を同期して再現する編集卓。

YouTube、Twitch、Discordで扱いが違う動画保存の論点を分け、ユーザーが用意した動画とコメントJSONを同期し、必要ならWebMで録画する方針に整理する。

安全な素材導線

ローカル動画最優先
Twitch本人VOD公式DL
YouTube URL埋め込み
Discord配信録画前提

方針は「動画URLから汎用DL」ではなく「権利ある素材を読み込む」。DiscordはOBS等で視聴中に録画する。

サービス別の判断

YouTube URL

公開動画の汎用DL機能は入れない。アプリでは埋め込み再生を中心にし、ユーザーが権利を持つローカル動画を読み込めるようにする。

Twitch VOD

自分のVOD/Clipは公式DL済みファイルを読み込む。第三者VODやLiveをURLから自動DLする導線は避ける。

Discord REC

Go Liveや画面共有は後から公式DLできる前提ではない。OBSなどで視聴中に録画した動画を素材にする。

WebM OUTPUT

ブラウザ録画はWebM保存が本命。編集や投稿向けにはMP4変換導線を追加する。

実装に入れるもの / 入れないもの

機能 判断 理由 UI文言
ローカル動画読み込み 採用 権利・保存場所・再現性が一番明確。 動画ファイルを選ぶ
YouTube URL再生 採用 DLせず埋め込み/再生に寄せられる。 YouTube URLで再生
Discordコメント取得 採用 Chrome拡張で表示DOMをユーザー操作で取得。完全履歴は保証しない。 表示中コメントを取得
WebM録画 採用 ブラウザ標準のMediaRecorderと相性が良い。 録画を開始
WebMからMP4変換 段階採用 まずはffmpeg/HandBrake手順表示。Electron化するなら変換ボタンを強化。 MP4へ変換する
YouTube/Twitch汎用動画DL 非採用 規約・権利・配布責任が重い。公式DL済み素材の読み込みに寄せる。 表示しない

ユーザーの作業フロー

1. 動画を用意

ローカル動画、OBS録画、Twitch公式DL済みVOD、またはYouTube URLを使う。

2. コメントを用意

JSONを読み込む。DiscordはChrome拡張で表示中DOMを取得する。

3. 表示を選ぶ

Discord風、Twitch風、YouTube風、LINE風、ニコ動風を切り替える。

4. 同期を調整

動画開始時刻、コメント範囲、表示密度、色、速度を微調整する。

5. 保存する

合成結果をWebMで録画。必要に応じてMP4変換の導線を使う。

短い結論

動画は「抜く」のではなく「持ち込む」。コメントは「見えている範囲を正直に取得」。出力は WebM を基本にし、必要な人へ MP4 変換を案内する。

SSOT候補

ローカル確認用資料。公開・告知・配布の前には、README、license、secret scan、personal path scan、生成ZIPの目視確認が必要。
